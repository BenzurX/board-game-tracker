# PROGRESS - Board Game Tracker

## Multiplayer Rooms (built 2026-07-23, shipped 2026-07-24 in v0.14)
`multiplayer` `cloudflare-worker` `shipped`
Cloudflare Worker + Durable Object backend with a full client (join-by-code, QR, live room bar, host/each-player scoring modes), deployed and live. Three of the original beta scope cuts have since been lifted and the host-disconnect one is much softened by the v0.22 presence grace window - read the detail file before assuming a documented limitation still holds.
→ [progress/multiplayer-rooms.md](progress/multiplayer-rooms.md)

## Group Join (built 2026-08-09, shipped in v0.19, cap raised in v0.20, renaming added in v0.22)
`multiplayer` `worker` `shipped`
One device can declare up to all 8 seats during create-room or join-room; they become full players whose scores that device enters, and since v0.22 the leader can rename them too. Deliberately locked at join time and bound to the leader's device - both were explicit calls, and the alternatives are written down in the detail file.
→ [progress/group-join.md](progress/group-join.md)

Centre card whose title text and border share one shimmer sweep, fired only on a real turn transition into a column this device scores for. Four variants were staged first; the chosen one is variant C in `stage/your-turn-toast.html`, and the other three are still there if the call needs revisiting.

## Multiplayer Resilience and Final Round (built 2026-08-15, shipped in v0.22)
`multiplayer` `worker` `farkle` `shipped`
Presence grace window, keepalive with silent reconnect and a blocking Reconnect dialog, auto-scroll to the live round and current column, rename-anyone-you-own, in-place New Game for a live room, turn-gated score entry, and a Farkle final lap measured in turn order. The grace window and the client retry budget are deliberately paired numbers, `refreshAlarm()` is now the only thing allowed to set the Durable Object's alarm, and rounds no longer necessarily start at column one - read the detail file before touching any of the three.
→ [progress/multiplayer-resilience.md](progress/multiplayer-resilience.md)

## Tracker Chrome Auto-Hide (rebuilt 2026-08-17, shipped in v0.23)
`ui` `scrolling` `shipped`
The three tracker bars now collapse together three seconds after the last manual scroll instead of by scroll position, and only real input - wheel, drag, scrolling key - brings them back, so the app's own auto-scrolls no longer flash them at a player who never touched the screen. The input-only reveal, the momentum grace period, the `scrollTop` correction and the short-board guard each exist for a specific failure - read the detail file before adjusting any of the four.
→ [progress/tracker-chrome-autohide.md](progress/tracker-chrome-autohide.md)

## Score Entry Fixes (built and shipped 2026-08-27 in v0.24)
`custom-games` `input` `mobile` `shipped`
Two fixes to how a custom game is scored: golf direction was being read from an unscoped `.dir-btn.active` query that matched the multiplayer section's button first, so every golf game crowned the highest total, and score fields now carry a ± button because no mobile keypad offers a minus key. The switch from `type="number"` to `type="text"` is what makes the sign toggle work at all - read the detail file before putting the number input back.
→ [progress/score-entry-fixes.md](progress/score-entry-fixes.md)

## Pip Redesign (built 2026-08-27 to 2026-08-29, shipped 2026-08-29 in v0.25 - milestone)
`design` `sound` `worker` `milestone` `shipped`
Major visual UI/UX rework, and the largest single change since Multiplayer Rooms. Full visual rebuild from a Claude Design handoff: one Pip theme in two modes, eight ink-on-accent player colours, a single physical button model, the die as the player counter across all three setup flows, and a procedural Web Audio layer with a pop and a victory fanfare. The review pass found the Worker had never moved to the new palette, which had been silently rejecting every colour change players made - read the detail file before touching the token aliases, the rotation rule, or where the fanfare fires.
→ [progress/pip-redesign.md](progress/pip-redesign.md)

## Solo Turn Order + Skyjo (built and shipped 2026-09-01 in v0.28)
`farkle` `skyjo` `bug-fix` `shipped`
Single-device play now enters scores one seat at a time in turn order (Farkle, Cribbage, Qwirkle, Yahtzee, Skyjo), reusing multiplayer's per-seat turn engine client-side - this closes the reported bug where a solo Farkle final round could end before every player actually took a turn. New game: Skyjo. Not yet tested on a real device - read the detail file for the two rounds of bugs found (a codex-agent review pass, then a Farkle-zero storage bug found after) before assuming the turn engine is fully proven out.
→ [progress/solo-turn-order.md](progress/solo-turn-order.md)

## Pipzee and Rules-Aware Setup (built 2026-09-06, shipped in v0.29)
`pipzee` `rules` `multiplayer` `ui` `codex` `shipped`
Pipzee replaces Yahtzee with a true category scorecard. Setup now applies game-specific player caps and endings: Gin Rummy is 2 only, Euchre 2-6 variants, Qwirkle 2-4, and Three Thirteen ends after 11 rounds. Skyjo and Qwirkle hide their unused controls; Skyjo now has multi-device rooms. The home library uses right-aligned ticket tabs to flag new and updated games. The Worker has been redeployed for its new game caps.

## Backlog
- The Worker has no final-round concept: `canScoreFor` will accept a score for a seat the final lap has closed, and `findNextUnsubmittedPlayerId` still cycles the turn onto one. Enforcement is client-side only, so a stale client could push a score the rules do not allow
- More games (round-by-round and category-based scoring)
- Payment/entitlement gating for multiplayer, deferred to before v1.0
- Host reassignment when the host disconnects mid-game (currently the room just loses host-only controls until they return)
